# 接入用例：运行控制与产物发布

本页展示运行中的 steer、interrupt，以及批量 `artifact.publish` 产物发布。

## 1. 运行中引导：Query 之后追加 Steer

`steer` 请求层是 `/api/steer`，流里体现为 `request.steer`。

```json
// 1) POST /api/query
{
  "requestId": "req_steer_001",
  "chatId": "chat_live_001",
  "agentKey": "auto",
  "role": "user",
  "message": "先给我一版三点总结，主题是我们新的 AGW 协议文档。",
  "stream": true
}
```

```json
// 2) POST /api/steer
{
  "requestId": "req_steer_002",
  "chatId": "chat_live_001",
  "runId": "run_live_001",
  "steerId": "steer_001",
  "agentKey": "auto",
  "teamId": "docs",
  "message": "补充一个要求：输出前先列出 HTTP API 和 SSE event 的边界，再继续完成总结。",
  "planningMode": false
}
```

```json
// 2) Response
{
  "accepted": true,
  "status": "accepted",
  "runId": "run_live_001",
  "steerId": "steer_001",
  "detail": "steer accepted"
}
```

## 2. 运行中中断：Interrupt -> `run.cancel`

请求层是 `/api/interrupt`，流里直接表现为 `run.cancel`，不会出现独立的 interrupt request 事件。

```json
// 1) POST /api/query
{
  "requestId": "req_interrupt_001",
  "chatId": "chat_live_002",
  "agentKey": "auto",
  "role": "user",
  "message": "帮我写一份很长的 AGW 协议对比说明，覆盖所有事件类型。",
  "stream": true
}
```

```json
// 2) POST /api/interrupt
{
  "requestId": "req_interrupt_002",
  "chatId": "chat_live_002",
  "runId": "run_live_002",
  "agentKey": "auto",
  "teamId": "docs",
  "message": "先停止当前回答，我要改需求。",
  "planningMode": false
}
```

```json
// 2) Response
{
  "accepted": true,
  "status": "accepted",
  "runId": "run_live_002",
  "detail": "interrupt accepted"
}
```

## 3. 文件产出物发布：一次工具调用，一条批量 `artifact.publish`

一次 `_artifact_publish_` 工具调用可以发布多个文件，并通过一条批量 `artifact.publish` 事件把这些文件发布到当前 chat；`runId` 仅用于标记来源 run。

```json
// 1) tool call (one invocation, multiple artifacts)
{
  "name": "_artifact_publish_",
  "arguments": {
    "artifacts": [
      {
        "path": "/workspace/reports/final-report.md",
        "description": "最终交付报告"
      },
      {
        "path": "/workspace/reports/summary.md",
        "name": "summary.md"
      }
    ]
  }
}
```
